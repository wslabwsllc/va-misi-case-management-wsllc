## Limitations (out of scope per specification 4.7 and plan 0.7)

- No production identity provider, password reset or self-registration.
- No malware scanning of attachments. MIME type and extension are browser claims; the leading bytes are checked for
  PDF, PNG, JPEG and DOCX, which catches renamed files but is not proof of safety. Files are always served as
  downloads with `nosniff` to limit exposure.
- A crash between storing an upload's bytes and committing its metadata can leave an unreferenced file until the next
  start, when the migrator removes it; such a file is never served.
- Attachments cannot be deleted (OQ-17), and there is no per-case count limit.
- The lookup contract is the Government definition (D1), which specifies only 200 and 404; a real service could
  differ on the errors it leaves undefined (D11, D12).
- No production monitoring, alerting, tracing backend or metrics dashboard; logs go to stdout only.
- No Government systems or data; all data is synthetic.
- Backup, disaster recovery and high availability are not addressed.
- Audit-trail immutability protects application operations only, not a database administrator.
- The health readiness probe is a liveness-style TCP/HTTP check, not a load test.
- No HTTPS: spec 4.5 serves the app on `http://localhost:8080`, so the auth cookie is not `Secure`, there is no HSTS
  and credentials cross the loopback interface unencrypted. Acceptable for local evaluation only.
- Sign-out clears the browser's cookie but does not revoke a copy captured before sign-out (stateless cookie
  authentication); such a copy stays valid until it expires (8 hours) or the user's security stamp changes.
- Role membership changes reach an open session within the one-minute revalidation interval (the member signs in again); permission, override and deactivation changes apply at the next request in this single-instance deployment.
- The CSP allows inline styles (`style-src 'unsafe-inline'`) because Blazor's reconnect and error UI set them; scripts
  are limited to the app's own origin.
- Demo passwords are a documented shared secret in `docker-compose.yml`; they protect nothing beyond the local demo.

- PWA installation and the service worker need HTTPS or localhost; on plain HTTP elsewhere the app runs without them.
  Offline use is limited to a static offline page by design (no case data on the device).
- Screenshots in test evidence cannot be redacted after capture; inputs for passwords and SSNs are masked when they are
  taken and all data is synthetic.

## Known gaps (tracked, not hidden)

- **SSN-shaped values in Git history (review F05, R24/R35).** Commits from 2026-10-16 to 2026-10-20 (`d4ab5ac`,
  `790c43e`, `55c3397`) contain SSN-shaped test values in issuable areas (123, 10 occurrences; 555; 111; the full values
  are deliberately not repeated here). They are synthetic placeholders, not any person's data, but potentially valid
  numbers. The current tree no longer uses them: `SyntheticSsnGuardTests` fails the build for any SSN-shaped literal
  outside the never-issued areas (000, 666, 900-999). The one remaining area-123 value is the example inside the
  Government's lookup contract (`docs/contracts/veteran-lookup.spec.openapi.yaml`), which is kept verbatim as delivered.
  **Decision (2026-10-21):** history is not rewritten; the occurrences are recorded instead. The reasons, the full list
  of commits, the command that finds them and the steps for a later rewrite are in
  [ADR 0017](adr/0017-ssn-shaped-values-in-git-history.md).

- Manual accessibility review (native file picker, download prompt, screen reader, zoom/reflow, real iOS/Android
  devices, reconnect) is not yet performed: [accessibility-review.md](accessibility-review.md).
- `docs/traceability.md` (requirement → evidence) is still owed by E1-S8.
